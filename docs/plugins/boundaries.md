# 插件安全与架构边界

插件属于可信构建期扩展，不是任意第三方代码沙箱。即便进入白名单，也只能通过宿主明确提供的能力工作。

## 允许

- 通过 `@achord/platform-plugin-sdk` 使用宿主公开的数据结构。
- 使用 manifest 声明能力、配置字段和后台操作。
- 通过宿主传入的字节、资源 ID 和受限任务接口处理数据。
- 将通用状态写入 `PluginInstallation`、`PluginRun` 和 `PluginResourceState`。
- 在宿主审查后使用固定版本依赖和明确列出的外部服务。

## 禁止

- 后台上传、解压或动态执行插件代码。
- 直接导入 Prisma Client、认证内部模块、数据库连接或服务器环境变量。
- 自行读取任意文件路径；文件访问必须由宿主按 storage key 完成路径校验。
- 绕过 Actor 权限、RLS、审计或既有附件可见范围。
- 在 Web 请求中执行批量扫描、图片压缩等长任务。
- 未声明能力时访问网络、文件、附件正文或发送通知。
- 在日志、审计 metadata 或 SSE payload 中写入密钥、令牌和文件正文。
- 修改主应用认证流程、权限判断、全局 CSS、路由中间件或部署入口。
- 使用无限重试、无超时网络请求、无并发限制的 CPU 密集任务。

## 数据库

- 插件数据库变化必须进入主仓库 migration。
- 新表默认启用 RLS；管理型插件数据只允许平台管理员访问。
- 插件删除不能级联删除核心业务数据。
- JSON 配置只保存非敏感值；密钥必须使用平台加密能力并禁止回显。

## 文件与网络

- storage key 必须由宿主解析和校验，插件不得拼接绝对路径或越过附件根目录。
- 新文件先写入私有临时位置，数据库条件切换成功后才能删除旧文件。
- 网络访问必须声明目标、超时、重试上限和失败策略，不得把客户数据发送到未审查服务。
- 下载或响应内容必须限制大小并验证类型，禁止直接执行远端内容。

## 任务与实时状态

- CPU 密集任务默认单并发并限制输入大小。
- Web 请求只创建任务；批量工作进入 pg-boss。
- 任务必须支持幂等、有限重试、暂停、继续、取消和失败清理。
- 进度使用 SSE 推送，事件只包含最小状态和资源 ID，不发送文件内容。

## 资源与故障

- 插件故障应保持核心业务可用；图片优化失败必须继续使用原附件。
- 文件替换采用“写新文件 → 条件更新数据库 → 删除旧文件”，禁止原地覆盖。
- 停用插件立即停止创建新任务，已经完成的数据不自动回滚。
- 插件版本变化后自动停用并使旧健康结果失效；重新检测通过前不得创建或继续任务。

## 审计与隐私

- 启停、配置、健康检测和管理员任务操作必须写审计记录。
- 审计只记录配置是否变化、状态和资源 ID，不记录敏感配置值。
- 插件只能处理当前动作授权范围内的数据，不得建立跨客户数据索引或缓存。
- 清理插件数据时不得级联删除核心业务记录。

## 生产依赖与部署

- 原生依赖必须固定版本并在 Node.js 24、GitHub Ubuntu 和 VPS Linux 验证。
- 原生依赖必须由主应用直接安装并从应用根目录加载，不得依赖 Turbopack 哈希别名。
- 部署前后执行 `pnpm verify:runtime-deps`，并拒绝仍引用 `sharp-<hash>` 的构建。
- 任何依赖或运行逻辑变化都必须提升插件版本，并保留可回滚的主项目提交。
